# Правила ИИ для проекта English Cheatsheet

## 1. Назначение проекта

Проект содержит компактную англоязычную грамматическую шпаргалку на русском языке.

Главная цель:

- объяснять грамматику кратко и структурно;
- использовать формулы, таблицы и короткие примеры;
- сохранять лёгкую печатную версию PDF;
- не добавлять материалы, не относящиеся к грамматике.

Пользователь обычно присылает изображения страниц или конспектов урока с репетитором. Эти изображения являются исходными материалами для извлечения и проверки грамматических тем, а не готовым содержимым PDF.

Общаться с владельцем проекта на русском языке.

## 2. Основные файлы

Рабочие файлы:

- `D:\vsprojects\ChatExport_2026-08-21\english_cheatsheet.html`
- `D:\vsprojects\ChatExport_2026-08-21\english_cheatsheet.pdf`

Исходником считается HTML-файл:

```text
D:\vsprojects\ChatExport_2026-08-21\english_cheatsheet.html
```

PDF является сгенерированным результатом и не редактируется вручную.

Все пути в сообщениях и командах указывать абсолютными.

## 3. Допустимое содержание

В шпаргалке разрешены только грамматические темы:

- порядок слов;
- части речи;
- `to be`;
- вопросы и отрицания;
- Present Simple;
- Present Continuous;
- Past Simple;
- Present Perfect;
- Future `will`;
- `be going to`;
- формы глагола `V1 / V2 / V3 / V-ing`;
- неправильные глаголы;
- артикли;
- `some / any / much / many`;
- `there is / there are`;
- предлоги времени и движения;
- `used to`;
- `be used to / get used to`;
- модальные глаголы;
- наречия частотности;
- наречия образа действия;
- сравнительная и превосходная степени;
- `as ... as`;
- притяжательный падеж;
- `W/H-questions`;
- `have got`;
- `like / love / hate + V-ing`;
- повелительное наклонение;
- таблица времён;
- алгоритм выбора формы;
- компактная итоговая грамматическая таблица.

### Специальное правило для `used to`

`used to` должен находиться только в отдельном разделе 7.

Не добавлять повторный самостоятельный блок `used to` в разделе 6 или других разделах. Допустимы только краткие перекрёстные ссылки, если они не создают дублирование материала.

## 4. Запрещённое содержание

Не добавлять и не возвращать:

- travel-блоки;
- рассказы о поездках;
- reading;
- story;
- pronunciation;
- vocabulary;
- тематическую лексику;
- лексику отеля, ресторана, транспорта и аэропорта;
- списки слов, не нужные для объяснения грамматики;
- упражнения, диалоги и задания, если они не нужны для объяснения грамматического правила;
- изображения, иллюстрации и декоративные SVG;
- внешние шрифты;
- внешние CSS/JS-ресурсы;
- внешние HTTP-запросы;
- Google Fonts и другие CDN-импорты.

Проверять не только видимый текст HTML, но и содержимое итогового PDF.

## 5. Структура HTML

Текущая структура документа:

- обложка;
- 12 грамматических разделов;
- навигация по разделам;
- footer на каждой странице.

Не менять структуру без необходимости.

Каждый грамматический раздел должен оставаться отдельным элементом:

```html
<section class="sheet page-break">
```

Заголовки разделов должны содержать нумерацию:

```html
<h2>6. Предлоги</h2>
```

Не удалять и не переименовывать CSS-классы без проверки всех мест их использования.

Существующую сортировку секций и автоматическую нумерацию страниц сохранять.

## 6. Стиль содержания

Текст должен быть:

- кратким;
- прикладным;
- ориентированным на уровень A1–A2;
- без длинных теоретических отступлений;
- с английским примером и коротким русским пояснением;
- с приоритетом формулы и сигнальных слов.

Предпочтительный формат:

```html
<div class="formula">
  SUBJECT + VERB + OBJECT
</div>

<div class="ex">
  <span class="en">I watch a film.</span><br>
  <span class="ru">Я смотрю фильм.</span>
</div>
```

Не использовать комментарии в HTML, если они не объясняют неочевидное техническое решение.

Не добавлять длинные пояснения ради заполнения страницы.

## 7. Добавление новой грамматической темы

При получении новой темы из сообщения или изображения:

1. Извлечь из материала только грамматическое содержание: правило, формулу, сигнальные слова, примеры и типичные ошибки.
2. Не переносить в шпаргалку изображения, оформление страницы, имена, даты, задания и нерелевантную лексику.
3. Если фрагмент изображения нечитаем или OCR даёт неоднозначный результат, не додумывать текст: запросить у пользователя уточнение конкретного места.
4. Проверить, не раскрыта ли тема уже в существующем разделе.
5. Если тема уже есть, дополнить существующий блок, а не создавать дубль.
6. Если тема новая, выбрать подходящий существующий раздел или создать новый грамматический раздел только при необходимости.
7. Добавить тему в оглавление, заголовок раздела, автоматическую нумерацию и footer, если это требуется структурой документа.
8. Оформить тему в формате: краткое правило → формула → 2–4 примера → типичная ошибка или ограничение.
9. Сохранить уровень A1–A2 и не превращать раздел в конспект урока.
10. Проверить печатную компоновку и пересобрать PDF.

Количество страниц не фиксировано. 13 страниц — базовый размер текущей версии, но при добавлении новых грамматических тем PDF может стать длиннее. Нельзя удалять полезный грамматический материал или ухудшать читаемость только ради сохранения 13 страниц.

При увеличении объёма:

- сначала использовать свободное место и уплотнить только затронутый раздел;
- затем добавить новые страницы с корректным `page-break` и footer;
- сохранить читаемый размер шрифта, таблиц и формул;
- не оставлять пустые страницы и страницы только с footer;
- обновить проверку ожидаемого количества страниц в отчёте.

## 8. Правила редактирования

Перед изменением:

1. Прочитать текущий HTML.
2. Найти нужный раздел и связанные CSS-правила.
3. Проверить, нет ли дублирования содержания.
4. Проверить, не повлияет ли изменение на переносы страниц и footer.

При изменении:

- не переписывать файл целиком без необходимости;
- не менять несвязанные разделы;
- не добавлять новые зависимости;
- не использовать внешние ресурсы;
- сохранять UTF-8;
- соблюдать существующий стиль HTML и CSS;
- не удалять рабочие блоки без явной причины;
- не оставлять старые фрагменты разметки;
- не оставлять временные подписи страниц вроде `08 / 15`, если они конфликтуют с автоматической нумерацией.

Особенно внимательно проверять секции 6 и 8: они близки к пределу высоты печатного листа.

## 9. Правила PDF и печати

Итоговый PDF должен:

- включать обложку и все грамматические разделы;
- иметь столько страниц, сколько необходимо для полного и читаемого материала;
- не иметь пустых страниц;
- не иметь страниц только с footer;
- не содержать изображения;
- содержать текстовый слой;
- иметь корректную нумерацию страниц;
- сохранять читаемость таблиц и формул.

Целевой файл:

```text
D:\vsprojects\ChatExport_2026-08-21\english_cheatsheet.pdf
```

Перед финальной сборкой проверить:

- `@import` отсутствует;
- внешние URL отсутствуют;
- `<img>` отсутствует;
- старые footer-фрагменты отсутствуют;
- количество секций соответствует числу грамматических разделов;
- количество footer-блоков соответствует количеству печатных страниц;
- `used to` не продублирован в разделе 6;
- секции 6 и 8 не переносят footer на следующую страницу.

Если новый блок увеличивает количество страниц, сначала:

1. сократить повторяющийся текст;
2. уменьшить вертикальные отступы конкретного раздела;
3. уплотнить таблицу или карточки;
4. применить локальный печатный класс.

Не уменьшать глобальный шрифт во всём документе без необходимости.

## 10. Сборка PDF

PDF собирать из HTML в headless-браузере.

Временный профиль браузера и проверочный PDF создавать только во временном месте и удалять после сборки.

Не оставлять в проекте:

- временные PDF;
- профили браузера;
- скриншоты;
- экспортированные изображения;
- промежуточные HTML-файлы;
- логи отладки.

После успешной проверки заменить:

```text
D:\vsprojects\ChatExport_2026-08-21\english_cheatsheet.pdf
```

на новую версию.

## 11. Обязательная проверка после каждой правки

Проверить HTML:

- файл существует;
- HTML не обрезан;
- количество секций соответствует структуре документа;
- количество заголовков `h2` соответствует количеству грамматических разделов;
- количество footer-блоков соответствует количеству печатных страниц;
- изображений — 0;
- внешних импортов — 0;
- старых footer-фрагментов — 0.

Проверить PDF:

- файл существует;
- количество страниц соответствует текущему объёму материала;
- количество изображений — 0;
- текстовый слой присутствует;
- нет travel/reading/pronunciation/story/vocabulary-содержания;
- есть темы `used to`, модальные глаголы и наречия;
- последняя страница не является пустой или страницей только с footer.

Проверить проект:

- временных файлов не осталось;
- изменены только необходимые файлы;
- HTML и PDF имеют актуальное время изменения;
- в коде нет `console.log`, `var_dump` и отладочных вставок.

## 12. Обработка ошибок

Не скрывать ошибки сборки и проверки.

Если PDF не собрался:

- не заменять рабочий PDF неполным файлом;
- сообщить точную причину;
- сохранить предыдущую корректную версию;
- проверить HTML и параметры headless-браузера.

Если количество страниц увеличилось:

- не удалять footer или контент случайно;
- определить секцию, вызвавшую переполнение;
- проверить, что увеличение вызвано новым содержанием, а не случайным переполнением;
- исправить только печатную компоновку затронутого раздела;
- пересобрать и повторить проверку.

Если проверка текста показывает запрещённую тему, удалить её из HTML и пересобрать PDF.

## 13. Формат отчёта после работы

После завершения сообщить кратко:

1. какие файлы изменены;
2. что именно исправлено;
3. результат сборки PDF;
4. количество страниц;
5. количество изображений;
6. результат проверки запрещённого содержания;
7. наличие или отсутствие временных файлов;
8. известные ограничения, если они остались.
